# v1.3.0: AI workspace, sound mixer, Hub

Agreed 2026-11-11. Builds on v1.2.5 (connected devices).

## Decisions

| Area | Decision |
|---|---|
| AI widgets: network | Approved sites only. The AI declares the hosts a widget needs; the user approves them once. Everything else stays blocked. Widgets can save their own small state. |
| AI tools | Both, tiered. Sandboxed JavaScript by default; a tool may ask for script mode (PowerShell / bash / Python), which needs the user's explicit approval, again after every change. |
| Hub | A standalone app for any always-on machine (Windows, Linux, Docker). It pairs like a device but only stores and forwards end-to-end encrypted data: it can't read files, states or AI requests. |

## 1. AI Artifacts

The AI Folder's `Visuals` subfolder becomes `AI Artifacts`: a general home for things the
assistant makes (visual pages today). Existing `Visuals` folders are renamed on first start. The
tool names (`show_visual` etc.) stay, so models keep working; the UI says "artifact".

## 2. AI widgets

Persistent desktop widgets the assistant writes on request ("make me a widget that…").

- **Where they live:** `AI Folder/AI Widgets/<name>/`, one folder per widget:
  - `index.html`: the widget.
  - `widget.json`: `{ id, title, hosts: [], width, height, createdAt }`.
  - `state.json`: the widget's saved state.

  The folder is the source of truth. Editing `index.html` yourself reloads the widget.
- **Tools:** `create_widget`, `update_widget`, `list_widgets`, `remove_widget` (write category:
  they follow the chat's permission mode).
- **Sandbox:** the same as visuals. A sandboxed frame with an opaque origin and no access to the
  app, plus a strict CSP. Scripts and styles may load from the public CDNs. `connect-src` and
  `img-src` list only the widget's approved hosts.
- **Approval:** a widget that declares hosts shows a native "Allow <widget> to reach: …" prompt
  when created or when its host list grows. Until approved, its network stays blocked. Approvals
  are stored per widget and listed in Settings > AI assistant > AI widgets, where they can be
  revoked.
- **State:** a small bridge (`aeroWidget.load()` / `aeroWidget.save(obj)`, 256 KB cap) over
  postMessage, stored in `state.json`.
- **On the desktop:** a normal widget (move, resize, lock, minimize to the dock). The header has
  reload, edit (opens the folder) and remove.

## 3. Tool creation workspace

The assistant can build its own tools, test them, and then use them like built-in ones.

- **Where they live:** `AI Folder/AI Tools/<name>/`:
  - `tool.json`: `{ name, description, input_schema, mode: 'sandbox' | 'script', runtime }`.
  - The code: `index.js` (sandbox), or `run.ps1` / `run.sh` / `run.py` (script).
- **Workspace tools for the AI:**
  - `create_tool` / `update_tool`: write the code and schema.
  - `test_tool`: run with a sample input and get the output and any errors back.
  - `list_tools`, `delete_tool`.
- **Using them:** saved tools join the AI's tool list as `tool_<name>`.
- **Sandbox mode (default):**
  - Runs in a hidden, sandboxed Chromium renderer with no Node and no network (CSP).
  - Exposes `export default async function (input, aero)` with
    `aero.call(toolName, input)`. That reaches the app's existing tools through the same
    permission checks as the AI itself, so a sandbox tool can never do more than the AI could.
  - Time limit 30 s.
- **Script mode:**
  - Runs the script with the interpreter, its working folder set to the tool's folder.
  - Input arrives as JSON on stdin; the result is read from stdout.
  - Time limit 60 s.
  - Needs approval: a new or changed script is "awaiting approval" until the user approves it
    in a dialog that shows the code. Approval is stored as a hash of the code, so any change
    needs approving again. Never runs unattended without that approval.
- **Settings > AI assistant > AI tools:** the list, with mode, approval state and code. Approve,
  revoke or delete from there.

## 4. Sound mixer and Bluetooth

A new widget: **Sound**.

- **Output device** picker and master volume and mute.
- **Per-app volumes:** one slider and a mute button per app playing sound, with its icon.
- **Bluetooth menu:**
  - The radio on or off.
  - Paired devices, with connected state and battery where available.
  - Connect or disconnect each device.
  - "Bluetooth settings…" to pair new ones.
- **Windows:**
  - Core Audio through a PowerShell worker: endpoints, endpoint volume, and per-session
    volume and mute.
  - Bluetooth through WinRT (`Windows.Devices.Radios`, `Windows.Devices.Enumeration`) and
    PnP. Where Windows has no supported connect call for a device class, the action opens
    Bluetooth settings.
- **Linux:**
  - Audio through `pactl` (PulseAudio / PipeWire-pulse): sinks and sink-inputs.
  - Bluetooth through `bluetoothctl`: power, devices, connect and disconnect, and battery
    via its info.

## 5. Hub: a relay that's always on

`hub/` in this repository: a small Node app with no Electron.

- **Runs as:**
  - `node hub.js`.
  - A Windows service or a systemd unit (an install script for each).
  - A Docker image.
  - Data lives in `~/.be-aero-hub` or `HUB_DATA`.
- **Identity and pairing:** the same as a device. It reuses `src/main/mesh` for the key pair,
  device ID, pinned TLS and the 6-digit pairing code. It appears in Settings > Devices as a Hub.
- **What it does:** stores and forwards. Each device has a mailbox on the Hub. When a device
  sends to a peer that's offline, it posts the message to the Hub for that peer instead. The
  peer collects its mail whenever it connects. The Hub keeps:
  - **State changes:** state-sync items for each offline peer. The newest version per key
    replaces older ones.
  - **AI bus messages:** tasks, questions and their late answers.
  - **Notifications and clipboard sends.**
  - **File Pool changes:** optional, with a size cap set on the Hub (default 2 GB). Larger
    files wait for a direct connection.
- **End-to-end encryption:** every item is encrypted for its recipient. An ephemeral ECDH P-256
  key with the recipient's device key derives an AES-256-GCM key; the item is also signed by the
  sender. The Hub only sees sender, recipient, size and time. Items expire after 30 days (set
  on the Hub).
- **Reachability:** devices connect to the Hub by address (LAN or internet: a port forward or a
  VPN). Discovery works on the LAN.
- **Status:** Settings > Devices shows each Hub (online, items waiting, storage used), and each
  device's last check-in.
